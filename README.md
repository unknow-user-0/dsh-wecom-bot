# dsh-wecom-bot

把**企业微信智能机器人**接进 [DeepSeek Harness](https://github.com/deepseek-ai/dsh)：长连接收消息、每个会话一个独立 DSH 会话、带人格与记忆，能在企微里跟人聊天，也能在你允许的范围内操作浏览器、看视频、收发文件、操作企微文档微盘邮件待办日程。

不是客服机器人。它更像一个被你拉进企业微信的成员：会打字、有记性、能看网页能看图看视频，群里要 @ 它，私聊不用。

---

## 它能做什么

| 能力 | 默认 | 说明 |
| --- | --- | --- |
| 聊天（私聊 / 群 @） | ✅ 开 | 每条会话一个独立 DSH 会话，独立工作区落盘 |
| 记忆 | ✅ 开 | 四层：人 / 场景 / 技能 / 公共。跨场景引用会标注来源 |
| 浏览器操作 | ✅ 开 | CDP 驱动本机 Edge/Chrome：打开网页、读页面、点按钮、填表、等接口返回。**默认只给管理员私聊**，面板里可放开到所有私聊；群聊永远不给 |
| 看视频 | ✅ 开 | 需要 `dsh-video-storyboard`，自动接它的 6 个工具（抽帧、缩放、探测、找台词、字幕带）。谁发的都看，没有开关 |
| 看抖音链接 | ✅ 开 | 发一条抖音链接（完整链接 / `v.douyin.com` 短链 / 一串视频号都行），它读标题、作者、数据、分类、文案和热评，再总结给你。只读，不能点赞不能发评论 |
| 收文件 | ✅ 开 | 私聊发来的都收（20 MB 内），群里发的文件不收。群里的视频照收 |
| 发文件 | 管理员 | 单文件 20 MB 内直接发；更大走微盘。面板里可放开到所有私聊 |
| 企微原生能力 | 需配 MCP | 文档/表格、待办、日程、会议、邮件、通讯录、微盘、群历史 |
| 转告别人 | ✅ 开 | 「帮我转告张三……」用 `wecom_send` 主动推。对方必须先跟机器人说过话 |

群里和普通成员**永远拿不到**浏览器、文件、微盘 —— 这不是配置项，是写死在代码里的边界。

（「看抖音链接」是这条边界的一个例外，因为它只做一件事：拿一个校验过的视频号去抖音自己的接口读公开信息。它不能导航到别处、不能点击、不能读文件、不能发消息。干活的时候开的是一个独立的后台标签页，不碰你正在看的页面，多个人同时发也不会互相冲掉。）

## 装它需要什么

1. **一个企业微信 + 一个智能机器人**
   企业微信管理后台 → 应用管理 → 智能机器人 → 创建 → 记下 `bot_id`（aibotid）和 `secret`。
   连接方式是长连接（`wss://openws.work.weixin.qq.com`），**不需要公网 IP、不需要备案、不需要回调地址**。

2. **DeepSeek Harness**（桌面版或 Web 版都行）
   插件用的是 `sessionController`，纯 CLI 宿主没有这个服务。

3. **Node ≥ 22.13**

## 安装

```
cd ~/.dsh/profiles/<你的profile>
pnpm add dsh-wecom-bot
```

然后在同一个 `package.json` 的 `dsh.profile.bundles` 数组里加一行 `"dsh-wecom-bot"`，重启 DSH。

左侧栏会出现「企业微信」图标，点进去就是面板。

> 想从源码装：`pnpm add file:/path/to/dsh-wecom-bot`。

## 第一次用

面板里的引导向导 4 步：

1. **填 bot_id + secret → 连接**
   连上了「连接」页第一张卡片的「长连接」会变绿。
2. **填你自己的 userid**
   用你的企业微信给机器人发一条私信，它会自动回你一条「你的 ID 是 xxx」（企微不会主动告知 ID，这句是插件回的）。
   把 ID 填进「用户」页，角色选 owner。
   **不自动认主**：第一次私聊的人不会自动变成管理员，必须手动填。
3. **选准入模式**
   默认白名单。也可以切「开放模式」：机器人被拉进群 / 被人私聊就都能聊。
4. **（可选）填 MCP 地址**
   见下一节。跳过也能用，只是少了群历史、发文件、文档那些。

## MCP：企微原生能力

企业微信给智能机器人配了一组 MCP 服务，8 个服务共 110 个工具。每个服务的地址是：

```
https://qyapi.weixin.qq.com/mcp/v2/bot/<service>?apikey=<你的KEY>
```

`<service>` 是下面 8 个之一，**每个服务的 apikey 都不一样**，在企微后台各自的页面里拿：

| service | 能干什么 | 硬限制 |
| --- | --- | --- |
| `msg` | 读群/私聊消息、发消息、发文件、下载媒体 | **只能读最近 7 天** |
| `doc` | Word/表格/智能表格/智能文档全套读写 | 没有删除文档的工具，删除要走客户端 |
| `todo` | 待办的增删改查完成 | `todo_get` 的 `items` 必填 |
| `schedule` | 日程增删改查、查多人空闲、会议室 | 会议室多数组织不可用 |
| `meeting` | 会议增删改查、拿转写 | `attendees` 参数不生效 |
| `disk` | 微盘上传/搜索/重命名/新建文件夹 | **没有删除**；机器人传的落「共享空间」 |
| `mail` | 收发邮件、搜索 | **没有删除**；只能查当前时刻前后 7 天 |
| `contact` | 按关键词搜成员 | **不支持全量罗列**，关键词必填 |

面板「管理员」页里，每个管理员可以填自己的那一套 URL（apikey 对应的是某个人，不是机器人）。
没填的就不显示那个服务。

地址存在 DSH 凭据库里（`.credentials.yaml`），配置文件里留的那份只是副本 —— 副本被清掉、或者换台机器只带过来了配置，插件会自己去凭据库找，不会当成「没配」。
「测一下」是真调一次**只读**接口（不往你微盘里写东西）：授权过期会被判失败，并给一个「去企微授权」的入口。

### 关于「7 天」

这不是本插件的限制，是企微 MCP 的限制。所以插件把这条写进了工具的说明里，并且**「查不到」和「没有」严格区分**：超出范围会明确告诉你「只能查最近 7 天」，不会返回空数组让模型以为没发生过。

长期记忆靠本插件自己的记忆库（无期限），MCP 只负责补最近这段上下文。

### 两个发消息的通道

- `message_aibot_send` —— 署名是**机器人**。默认走这个。
- `message_send` —— 署名是**授权的那位真人**。默认关，且需要管理员在对话里明确说「用我的身份发……」才会触发，防止对外分发时被人拿去冒充。

## 面板

五格，按「配置的时候会一起想的事情」分组 —— 不是照代码里的模块切的。
每格只回答一个问题：连得上吗、谁能用、它是什么样的、会做哪些事、出过什么事。

| 页 | 里面有什么 |
| --- | --- |
| 连接 | 连没连上、数据目录、最近 30 条收发 / bot_id 与 secret、断开重连、会话映射 / 按 token 计的每日额度（全局 + 每会话） |
| 用户 | 加/删管理员、主人私聊长任务档位（**默认开**）、每人的 8 个 MCP 地址（可单独测）/ 白名单 ⇄ 开放模式、白名单人和群、连发合并（对方停顿几秒算说完）、工作区目录（可迁移） |
| 自我 | 机器人名字（留空则从群里 @ 前缀自动学）、选人格、新建 / 另存为 / 删除、在线编辑、记忆开关、分层统计、搜索、逐条删 |
| 功能 | 浏览器操作三档、发文件权限、上下文补齐（水位 + 分批）、占位文案与占位图、视频浏览（yt-dlp 安装 / 视频站登录 / 语音转文字 ASR 合为一项） |
| 日志 | 实时日志（含脱敏） |

---

### 长任务档位（默认开，只影响主人私聊）

主人私聊的 `wecom-owner` preset 常挂两个插件：

- `tool-jobs` —— 后台任务（`job_list` / `job_output` / `job_kill`）。耗时的活丢后台跑，机器人先回你一句，你继续聊别的，跑完再取结果。关着的话，一个跑五分钟的活会把会话占死。
- `tool-schedule` —— 定时任务（`schedule_create` / `list` / `view` / `edit`）。让它到点自己干活，比如「每天早上九点把昨天的订单汇总发我」。

开关只是临时藏/露这两套工具（`tools.restrict`），**不会换 preset、不重建会话、不断上下文** —— 随时开随时用。只影响主人（第一个管理员）私聊那一档；群聊和普通成员用 `wecom-social`，永远拿不到这两个。

## 会话怎么组织

- 每一个企微会话（一个私聊 or 一个群）对应一个**独立的 DSH 会话**，落在工作区「企业微信 · AI」下（目录可改）。
- 档位分两档，按「是谁在说话」定：
  - `owner` —— 管理员私聊：人格 + 全部工具 + 浏览器 + 视频 + 文件
  - `social` —— 群聊 / 普通成员：只有企微社交工具、看视频、看抖音链接，零本地能力
- 群被 @ 时，会先用 MCP 把这个群从「上次同步」到现在的消息补进会话历史（只写不发，不惊动模型），再把当前这条交给模型。
- 断线重连后，同样用 MCP 补拉断线期间的消息。

## 连发合并

企微没有「正在输入」提示，所以对方连发几条时：

1. 先回一个占位（默认 `emmm...`，也可以换成一张自己的图）
2. 等对方停顿（默认私聊 2.5 秒、群聊 5 秒，可在「用户」页调 0.5~10 秒）
3. 攒齐了再一起处理，**只回复最后一条的消息 ID**

上限：私聊最多等 8 秒、群聊 15 秒。

### 占位可以是图

面板「功能」栏的「收到消息先回一句」里，除了文字还能从本地选一张图当占位。
文字、图片各有一个开关：只开文字就只发文字，只开图就只发图，两个都开就**先发文字再发图**。

⚠ 企微的图片只认 `media_id`，没有「直接发个 URL」这条路，`media_id` 得先拿
`media_upload` 换，而这个接口在 disk / mail / doc 服务（MCP）里。**没配这三个服务之一，
占位图发不出去**，会降级成只发文字，面板上也会直接提示原因。这是企微协议的限制。

动图（GIF / 动画 WebP）能用，但太大就会被自动抽帧：企微那边的图片有体积上限，
而 GIF 是调色板格式，缩边重采样反而会让文件**变大**（实测 2 MB 缩到 0.7 倍变成 6.4 MB），
真正的体积杠杆只有「帧数 × 像素数」。所以超预算的动图会被**抽掉一部分帧**、保持原尺寸，
并把每帧的显示时长按比例放大，**总播放时长和播放速度都不变**，动画也不会被压成静图。

选完图面板会直接告诉你结果，例如「动图 30 帧太大（2.0 MB），会自动抽成 15 帧，
总时长还是 2.4 秒，播放速度不变」——先看见代价，而不是等消息发到对面才发现少了帧。

## 额度

按 token 算，两层：全局每天 + 每个会话每天（一个私聊和一个群各算一个个体）。
单位可选百万 / 千万 / 亿，也可以关掉不限制。管理员默认不限制。
超了会礼貌告知，当天不再处理。

另有每分钟条数上限防刷屏（默认 30）。

---

## 安全边界（写死的，不是配置）

- 群聊和普通成员：没有浏览器、没有文件、没有微盘、没有画图。
- 企微插件建的会话**不挂 shell 工具**（preset 里就没有），所以不存在「远程敲命令」这条路径。
- 给用户发文件默认只允许管理员。
- MCP 写操作没有开关：只有配了自己 MCP 的管理员能调，且每个管理员只能用自己的那套。
- MCP 以真人身份发消息同样没有开关，但必须管理员原话里出现「用我的身份」。
- 日志里的 apikey / secret / token / `sk-*` 全部脱敏。
- 凭据优先存 DSH 凭据库，没有凭据服务时退内存（面板上会明确显示「内存（重启会丢）」）。

---

## 和 im-union 一起用会打架

企微智能机器人**同一时间只允许一个连接**，新订阅会踢掉旧的。

如果你之前装过 `dsh-im-union` 并且开着企微账号，装本插件前先去那边停用，否则两个插件会互相踢下线。收到 `disconnected_event` 后本插件**不会自动重连**（防互踢乒乓），需要手动点重连。

## 开发

```
node dev/smoke.mjs        # 插件装配冒烟：路由、提示词变量、事件监听
node dev/tools-check.mjs  # 工具 schema 检查（不连 DSH 不连企微）
node dev/e2e.mjs          # 端到端：假企微服务 + 假宿主 + 真插件
node dev/render-pages.mjs # 把面板 5 个版块渲染成 HTML 快照到 .snap/
node dev/tab-dirty.mjs    # 「有改动」圆点有没有亮错格（合并版块后容易串）
node dev/names.mjs        # 剥 @ 前缀 / 旧名字别名 / 人格读写
node dev/real-probe.mjs   # 用真凭据连真企微长连接
```

`dev/fake-wecom.js` 是一个照着企微帧格式写的假服务，可以单独跑：

```
node dev/fake-wecom.js --port 18081
curl -X POST http://127.0.0.1:18081/inbound -H 'content-type: application/json' \
  -d '{"text":"在吗","userid":"u1","chattype":"single"}'
```

插件侧把 `DSH_WECOM_WS_URL` 指到它就能在没有真机器人的情况下调完整链路。

## 已知限制

- **企微自己不回任何消息**。配置成 API 模式后，用户看到的每一句话都是插件发的。
- 长连接**没有文件外发帧**，发文件必须走 MCP（`media_upload` + `message_aibot_send`）。
- 回调里**没有 quote 字段**，所以拿不到「用户在引用哪条消息」。
- 也**没有任何拉取群历史的长连接帧**，群上下文只能靠 MCP 的 7 天窗口。
- 群里未 @ 机器人的消息企微**根本不推**（长连接和 StreamableHttp 都一样），所以群的水位只能停在上次被 @ 的时刻；私聊才是「收到就更新」。
- 主动推送**只对已经跟机器人说过话的会话**有效（企微侧只有那时才创建会话实体）。所以「从来没找过它的人」是推不进去的。
- 微盘和文档**没有删除接口**，该删的时候只能提醒你去手动删。
- 桌面控制能力没有做（没有 robotjs / nut.js），也没有 shell —— 会话里只挂浏览器和企微工具。
